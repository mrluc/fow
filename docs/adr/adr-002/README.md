# ADR-002: Displaying bundled assets without reading their pixels

Proposed, 2026-11-04. Keep the startup document at the website's real HTTPS origin. Frontier now uses CSS sprite darkening instead of the checkerboard canvas mask. Accept that images which require script-readable pixels are unsupported by the custom scheme for now. A future WebView may expose narrowly scoped native asset reads to JavaScript; no fetch patch or bridge is part of the current implementation.

`filter: brightness(.45)` darkens RGB and preserves alpha. It therefore darkens the tree itself rather than drawing a dark rectangle over its transparent background. Preserve the existing drop-shadow when composing filters. Do not substitute `opacity`, which also makes the sprite see-through. Inline SVG filters can use SourceAlpha to constrain procedural texture, without exposing pixels to JavaScript; that option is researched but not runtime-tested. Loading a sprite as an external CSS mask is not a demonstrated escape: mask resources require anonymous CORS fetching.

JavaScript can read encoded image bytes without canvas: `fetch(url).then(r => r.arrayBuffer())`, or `blob()`. The response must be same-origin or authorized by CORS, and the request must pass the browser's other loading policies. `no-cors` does not grant readable bytes. Display permission for an image is deliberately weaker than permission to inspect its contents. A future WebView could install an early JavaScript shim around `fetch()` and route only `fog-of-war-assets://` requests through a native message handler. Ordinary URLs would keep the original fetch behavior. The native side would validate the scheme/path, return status, MIME type and bytes, and avoid turning this into an unrestricted file-read API. This is a proposed escape hatch, not implemented or tested. It must be installed before application scripts and should be checked against Response/Request semantics, streaming, aborts and redirects before relying on it.

A loopback asset server remains a platform-dependent alternative, not a proven universal fix. The real website's Phoenix headers cannot authorize responses served by a different local server. The local server must send its own appropriate CORS headers; the startup document may also need CSP permissions. Neither overrides an earlier WebKit load rejection. Loading the whole document from localhost instead changes its origin and requires revisiting LiveView's socket URL, origin checks, cookies and recovery; that is a different architecture.

See [native results](native-results.md) for the observations that led to this trade-off, as well as [CSS findings](css-findings.md), [loopback findings](loopback-findings.md), and [native observations and reproduction](native-results.md). Frontier’s fog definition was changed to CSS sprite darkening; wrapper and bridge behavior was not changed.
